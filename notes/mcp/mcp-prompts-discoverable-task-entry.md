# MCP Prompts｜让外部系统提供可发现的任务入口 🧭

- Source｜来源：Model Context Protocol Specification
- Type｜类型：AI 产品方法观察 / MCP Prompts / Task Entry / Prompt Template / User-controlled Invocation
- Link｜链接：https://modelcontextprotocol.io/specification/2025-11-25/server/prompts

当 AI 应用连接的外部系统越来越多，用户面对的不只是更多数据和工具，也会面对一个新的问题：我现在可以让这个系统帮我完成哪些具体任务？如果入口仍然只是一个空白对话框，外部能力再丰富，也很难被稳定地发现和使用。

MCP Prompts 提供的是一种由 Server 暴露、可被客户端列出和获取的提示模板机制。它把外部系统中重复出现的任务意图做成可发现入口，让用户可以在明确控制下选择一个任务，再补充所需参数，而不是每次从零描述需求。

---

## What It Is｜它是什么 🧩

在 MCP 的语境里，Prompts 是 Server 提供的可复用提示模板。客户端可以发现这些模板，读取它们的说明和参数需求，并在用户选择后获得用于启动任务的消息内容。

它和普通的“收藏 Prompt”不同。普通 Prompt 往往留在个人笔记或某个应用内部；MCP Prompts 则把任务入口与具体外部系统绑定。一个代码仓库、设计系统或业务平台可以声明：它支持哪些常见协作任务，完成这些任务还需要哪些变量。

关键点在于调用权。Prompts 是用户控制的能力，通常由用户主动选择，而不是模型在后台自行触发。它的作用是帮助用户组织任务，不是直接替模型执行外部操作。

---

## Why It Matters｜为什么值得关注 💡

很多 AI 产品已经能连接数据源和工具，但连接本身并不会自动形成好的体验。用户仍可能不知道怎样提问、该提供哪些上下文，或一个系统最适合被用来解决什么问题。

这正是 MCP Prompts 的产品价值：把“系统能力”翻译成用户能识别的任务入口。例如，不是让用户面对一个“项目管理系统连接成功”的状态，而是提供“总结本周项目风险”“根据当前事项生成交接说明”这类清晰目标。用户能够先理解任务，再决定是否使用相关上下文和工具。

对平台而言，这也是减少模糊输入的一种方式。模板把必要参数、角色口径和结果期待提前表达出来，既降低用户起步成本，也使后续 AI 输出更贴近真实工作流。

---

## Relationship to Resources and Tools｜与 Resources、Tools 的关系 ⚙️

MCP 的不同能力类型解决的是不同层次的问题。Resources 提供可被应用读取的上下文，帮助 AI 知道相关资料在哪里；Tools 提供可调用的外部动作，让模型能够执行查询、写入或操作；Prompts 则把这些能力包装成用户能够主动选择的任务开端。

可以把它们理解为三个互补问题：有哪些信息可以被带入任务，系统能做哪些动作，以及用户可以从什么目标开始。Prompts 不替代 Resources 或 Tools，而是为它们提供更清晰的使用入口。

这种区分很重要。若把 Prompts 误当成自动化工具，就可能让用户难以判断何时会触发外部操作；若把它仅看成文案模板，又会忽略它对任务发现和上下文组织的作用。

---

## Use Case｜适用场景 📌

适合使用 MCP Prompts 的，通常是有稳定重复任务、但每次都需要少量变量的外部系统。比如代码平台可以提供“生成变更说明”“解释构建失败原因”的入口；知识库可以提供“基于指定项目整理决策记录”；客户支持系统可以提供“按产品版本汇总高频问题”。

在这些场景中，模板不应替用户隐藏关键选择。一个好的任务入口会说明需要什么输入、可能使用哪些信息，并允许用户在发送前补充或调整。这样，AI 的便利不会以失去任务主导权为代价。

对于复杂任务，Prompts 还可以充当工作流的第一步。它先帮助用户把目标表达成结构化请求，再由后续 Agent、Resources 或 Tools 接续处理。相比直接让模型猜测用户意图，这种路径更可解释，也更容易复盘。

## Product Insight｜产品观察 🔍

AI 产品里的空白输入框很灵活，但它经常把任务定义成本转移给用户。用户不仅要知道自己想做什么，还要知道如何用模型能够理解的方式表达出来。

MCP Prompts 提示了一种更接近产品设计的思路：把高价值、可重复的任务变成可浏览的入口。入口名称、说明、参数和预览共同构成任务发现体验。用户看到的不再是抽象的“已连接某个系统”，而是可选择的下一步。

这也要求设计者控制入口数量和层级。如果每个 Server 暴露几十个相近模板，用户会重新陷入选择困难。真正值得提供的，是目标明确、输入可控、能够带来稳定结果的任务，而不是把所有内部操作都包装成 Prompt。

---

## Reusable Value｜可复用价值 🔁

在设计 AI 工作台、企业助手或个人知识工具时，可以用这一模式检查任务入口是否足够清晰：用户能否快速看出系统擅长什么；每个入口是否说明了所需资料；开始前能否编辑参数；结果生成后是否能继续交给下一步工作流。

它同样适用于非 MCP 的产品。任何连接多个系统的 AI 应用，都可以把常用目标做成受控模板，而不是要求用户记住复杂指令。区别在于，MCP Prompts 给这种模式提供了跨客户端、跨 Server 的统一表达方式。

---

## Productization Direction｜产品化方向 🚀

未来的 AI 工具连接中心可以把 Prompts 做成任务目录：按角色、系统、频率和风险等级展示推荐入口。用户选择后，界面再展示参数表单、数据范围和可能调用的能力，必要时要求确认。

对企业场景而言，管理员还可以维护经过审核的任务模板，把组织内常见流程沉淀为可复用入口，同时保留权限和版本管理。产品的价值不只是“连上更多 MCP Server”，而是让连接后的能力更容易被发现、理解和正确启动。

---

## Product Observation｜进一步观察

AI 产品成熟的一个标志，是把技术连接转化成用户可理解的任务选择。Resources 让系统获得信息，Tools 让系统具备行动能力，Prompts 则帮助用户从一个明确目标开始协作。

当任务入口被设计得足够清楚，用户不需要先学习协议或工具名称，也能在需要时把外部系统的能力纳入自己的工作流。
